# Matched indoor power and caster diagnostic

This opt-in screen investigates three challenging images selected from the verified 24-scene natural mixture. It compares each original job with an aggregate main-lamp power cap, a broad fill for a single spot, both treatments together, and a caster-off diagnostic. The cap and fill are sampled-scene controls; they do not inspect an image or reject samples. These are selected stress cases and cannot establish mixture prevalence or detector performance.

The transform verifies each re-prepared job against the original study's normalized job hash before making any treatment changes. The lighting-only variants must retain exact full and visible masks. Caster-off differences are reported separately: they are not claimed as paired lighting-only evidence. Runtime resolution may reposition or omit lights; inspect actual recorded settings and diagnostics.

Prepare a new portable source/asset bundle from the verified natural study configuration and assets. Preserve the original study identity and normalized hashes of jobs `003-base-fast`, `008-base-fast` and `018-base-fast` in the specification, with the bundle, bootstrap, CLI and remote source hashes. Seal the bundled verifier and postprocessor with the same source version. Do not reuse historical temporary inputs, rate logs or budget baselines: independently verify current source and asset fingerprints, account balance, active assignments, all prior attempt costs, remote time budget and watchdog deadline. The shared supervisor currently applies an aggregate 3-CU cap, stricter than the round's 5-CU ceiling.

Launch the parent lighting-refinement supervisor using `--scripts-dir experiments/blenderproc/studies/coordinated-candidate/indoor_followup`, a fresh output directory, verified L4 rate evidence, a before-first-attempt idle usage snapshot and a conservative reserve for all earlier attempts. Its controller independently retrieves and verifies the archive and attempts runtime shutdown. An inaccessible host, network failure or invalid credentials can still prevent recovery or shutdown; check the final controller status.

After shutdown and retrieval, run `postprocess.py --run-dir RUN --input-dir INPUT --output FRESH_REVIEW` with the project's Python environment. It verifies bundle and archive hashes, source identity, output checksums, matching conditions and stop confirmation; incomplete results are labeled and return a failure status. The gallery compares all five variants and records caster mask differences. Any manual reconstruction of a bundle must be checked by `unpack_bundle` and assigned a new identity; do not relabel modified content with an earlier fingerprint.
